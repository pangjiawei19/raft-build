# Agent 任务与用户待答事项

2026 年 11 月 17 日，撤回统一指定验收人及协调者主消息汇总的自定义规则，共享 Agent 指南恢复为 `upstream/main` 的原文。

## 任务完成与明确的验收要求

任务流程已恢复为当前上游规则，不再为所有交付统一要求指定验收人。启用任务会话时，Agent 完成工作后可以直接将任务标为 `done`，并在提出请求或参与讨论的位置汇报。用户明确要求先看结果，或任务仍需他人决定、输入及其他工作时，保持 `in_progress`，将任务转交给当前需要行动的人并写明原因。

未启用任务会话的旧模式继续沿用上游的 `in_review` 和批准后 `done` 流程。该兼容路径不增加“缺少验收人时必须请求用户指定”的自定义要求。任务编号、负责人、历史和附件继续使用原记录。

具体任务明确要求复核或用户本人验收时，继续遵守该约定。协调沟通不自动获得验收或操作权限；任务标为完成也不扩大执行权限。用户的方向选择、方案采用和需单独授权的操作，继续按已有要求等待决定。

## 用户从哪里看到待答问题

待答问题沿用上游的提问、任务交接和通知机制，不再要求由协调者或负责人另发频道主消息汇总并提及用户。

用户需要在具体选项间作出决定后工作才能继续时，使用一张 `question:ask` 卡片集中提出相关问题；答案会以回复形式提及提问 Agent。正在进行的讨论或开放问题继续使用原对话；问题卡片不可用时按上游提示改用普通消息。详细用法见[问题卡片说明](../manual/agent-knowledge/action-cards.md)。

启用任务会话时，任务等待他人的决定或输入，就保持 `in_progress` 并转交给那个人，写明需要什么；已有通知时不再重复发送同一事项。回复位置、负责人汇报和线程习惯均沿用上游默认规则。

先使用新版收件箱、未读提示、提及和问题卡片观察实际体验。按需协调的上游方案仍可查阅，但不作为本仓库额外注入的默认流程。

## 提示与记忆如何保持一致

通用规则集中在 `packages/shared/src/raftCliGuide.ts`，托管 Daemon、外部 Agent 上下文和 CLI 操作手册共同使用。修改后生成手册，并验证各运行时提示快照。

此前自定义的“所有交付都要取得验收人批准”和“协调者必须在主消息汇总用户待答事项”均已撤回。具体项目已有的有效委派及用户明确的验收要求继续保留。

更新磁盘配置后，运行中的模型需要重新读取记忆。普通重启保留原生会话与工作目录，启动时加载新的职责和提示；无需为此重置会话或清空工作区。已有项目应按其明确授权和验收要求同步，不能根据新默认规则代替用户批准既有的人类验收事项。

## 验收方式

自动检查覆盖托管与外部 Agent 的新旧任务模式、生成手册一致性和各运行时提示快照；要求强制汇总的专用测试已移除。

2026 年 11 月 5 日及 6 日的真实验收记录保留为当时自定义规则的历史证据，不作为恢复上游默认流程后的行为要求。

2026 年 11 月 17 日已按用户授权同步本机现有 Agent：清理三个角色描述、九份当前记忆和相关协作资料；投资团队规范以１．０．１仅调整沟通条款，保留明确的项目验收委派及暂停要求。十三项任务会话索引与约束检查通过后，仅为当前本地工作区启用 `task_v2_conversations_v0`。九个 Agent 均以原会话完成只读维护确认。

同步重启曾触发五个历史任务自动收口，已纠正恢复同步前的状态与关联，保留原事件并追加纠正审计；新产生的五个讨论区已软删除退役，消息未物理删除。最终核对原有１６６个任务的业务字段保持，修复涉及的修订号及更新时间保留新审计。具体备份、回执、文件摘要及纠正记录在本机 `.slockdev/raft-build/upstream-agent-rules-20261117/`，不纳入版本控制。
