# PM 内部验收与用户待答事项真实验收

历史记录：下文描述当时的自定义流程。统一验收和主消息汇总规则已于 2026 年 11 月 17 日撤回，当前行为见[Agent 任务与用户待答事项](./agent-task-review-and-user-questions.md)。

日期：２０２６年１１月５日。

## 调整范围

用户授权由 PM 组织内部任务验收，将需要用户确认的问题汇总到项目频道主消息并直接提及用户，同时同步通用提示、当前 PM 的职责与记忆，保留现有任务和数据。

原通用提示要求所有工作进入 `in_review` 后等待人类批准；线程规则偏向在原线程继续回复，汇报规则也没有明确允许 PM 汇总他人的交付。此次统一调整这三处行为约定：

- 内部交付由项目 PM 组织专业复核，记录验收依据，满足原范围后更新原任务为 `done`；明确的人类验收要求与用户决定继续保留。
- 专业讨论留在原任务线程；用户待答事项由 PM 在授权项目频道的主消息汇总并直接提及用户，附依据入口和回答后的下一步。
- PM 可以汇总已复核的团队交付与未决事项；问题发生变化时更新汇总，已读不作为已经回答。

规则集中于共享 CLI 指南构建器，同时生成操作手册，更新托管提示快照，并修正任务认领操作手册中旧的人类验收表述。操作说明见 [Agent 内部验收与用户待答事项](./agent-task-review-and-user-questions.md)。

## 本地配置与生效

通过正式 API 只更新目标项目 PM 的职责说明，保留其运行时、模型、会话及权限。同步该 PM 的 `MEMORY.md`、项目说明、工作记录，以及三名专业成员的记忆索引，共六个既有文件；原来所有任务都等待人类验收的约定标为历史。

开发服务热重载后，对空闲 PM 做普通重启，未重置会话或工作区。核验其原生会话的指令记录，确认新内部验收和主频道提及规则已进入当前会话；原会话 ID 保持。

其他项目既有的明确用户验收要求保持，本轮本地角色同步以目标投资团队为范围。

## 真实运行结果

从已有汇总任务的原线程向真实 PM 发送一次验收指令，要求按原范围、交付及专业意见逐项核对，保留编号、负责人、记录和附件。

PM 在各原任务线程记录验收人、交付依据、专业复核及结论，随后完成八个内部任务：频道任务 ＃1—＃6、＃8、＃9。原流程稿任务 ＃7 保持 `in_review`，继续等待用户讨论和选择；顾问、策略师的两项同次原私聊交付也得到收口。

PM 起初新增了一张协调卡，收到沿用原任务的具体指示后，确认重复并将其标为 `closed`，保留该卡及原因记录，继续使用原汇总任务。原汇总任务的标题与验收范围通过正常修订更新，原历史保留。

PM 在项目频道主消息发布最终阶段总结，直接提及用户，集中列出两项待答，包含原验收线程和流程草案入口，以及答复后的下一步。数据库中存在对应的人类提及记录，通知时间非空。页面验收确认用户提及可点击、问题位于频道主消息；最终看板为待办 0、进行中 0、待确认 1、完成 8、已关闭 1。

PM 将最终状态、两项待答及当前主消息入口同步回记忆与项目笔记，并通知三名专业成员新协作规则。首条只询问研究范围的主消息保留历史，最终汇总明确声明以最新待答为准。

此次验收没有启动策略回测、CLI 安装、业务代码修改、账户接入或交易。
